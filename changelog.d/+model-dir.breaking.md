Model import now fully removes a previous model import from the output
directory, including subdirectories, instead of only the top-level files.
This prevents outdated build files or extensions from previous imports from
interfering with the new import.
Files inside AMICI-generated subdirectories, such as the model package
directory, are removed as well.
To ensure that only files created by AMICI are removed, AMICI now writes a
marker file to the model directory, recording the files it created.
Model import fails with a `FileExistsError` if the output directory contains
other top-level files or directories.
This also applies to `force_import=True` (`PetabImporter.import_module`) and
`compile_=True` (PEtab v1 `import_petab_problem`).
Previously, the latter removed the whole output directory for non-JAX models.
PEtab v1 `import_petab_problem` no longer raises a `ValueError` for
non-empty output directories without a usable model, but re-imports the model
if the directory only contains files created by AMICI, and raises a
`FileExistsError` otherwise.
Model directories created by earlier AMICI versions are recognized and
removed if they only contain files generated by AMICI.

The PEtab importers use the marker file to detect model directories left
behind by failed or interrupted imports, or created by a different AMICI
version, and import the model again without raising an error.
